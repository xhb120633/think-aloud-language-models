# Research code and reproduction guide

Run commands from the repository root. The original scientific source is supplied as a snapshot; a source listing is not a claim that every historical analysis has been rerun or that default settings reproduce the manuscript.

## 1. Data-only inspection (verified)

```sh
python examples/inspect_data.py
```

No installations, credentials, audio, GPU, or saved model output are required. See [examples](../examples/README.md) for pandas access.

## 2. Environments

Python 3.10+ is the source target. `requirements.txt` lists analysis imports; `requirements-models.txt` adds PyTorch, Transformers, and the OpenAI SDK. These are dependency inventories, not a recovered historical lockfile. The validation environment is documented in the release provenance.

```sh
python -m venv .venv
# Activate .venv for your shell, then:
python -m pip install -r requirements-models.txt
```

Install vLLM separately if using that backend; GPU and CUDA compatibility depends on your environment. API credentials belong in `OPENAI_API_KEY`, and gated model access can use `HF_TOKEN`. Neither is needed to download or inspect the data. An API-backed experiment sends its prompts, including any selected transcripts, to the configured provider and may incur costs.

## 3. Generation entry points

Use `--help` to inspect options before generation. These examples illustrate existing interfaces, not exact historical run settings:

```sh
python exp1_llm_prediction.py --help
python exp2_in_context.py --help
python exp1_neural_training.py --help
python exp_superficial_claims.py --help
python embed_cot_data.py --help
```

For a neural-baseline run from the core CSVs:

```sh
python exp1_neural_training.py --data_size small --model_type value_based
```

For same-trial human-transcript prediction, explicitly select a backend and model; for example:

```sh
python exp1_llm_prediction.py --data_size small --mode human --model_type huggingface --model_name meta-llama/Meta-Llama-3.1-70B-Instruct
```

This is a large-model run, not a quick-start test. Review memory requirements and access before running it. Modes, generation parameters, context settings, and seeds must be matched to the intended analysis. The source's generic defaults (including model names and token budgets) are not a paper run manifest.

## 4. Paper-to-code map and required artifacts

| Paper component | Entry point | Additional inputs beyond the two CSVs |
|---|---|---|
| Figure 1 corpus description / Figure S7 benchmark comparisons | `analyze_behavior_replication.py` | Historical reference workbook and Choices13k files for benchmark comparisons; use the supplied example for basic corpus counts |
| Figure 2 model schematic | Static figure in manuscript | No analysis script |
| Figure 3 / model comparison tables | `analyze_model_comparison.py` | Saved predictions in `results/exp1_llm_prediction/`, baseline outputs in `results/model_result/`, and human-rater workbooks for human comparisons |
| Figure 4 / in-context comparisons | `analyze_in_context.py` | Saved `results/exp2_in_context/` and/or `results/exp2_in_context_pt/` outputs and baselines |
| Figure 5 / embedding comparisons | `analyze_cot_embeddings_similarity.py` | Saved model-generated reasoning and `results/embeddings/` |
| Figure S6 transcription quality | `analyze_transcription_quality.py` | `data/behavioral_text_quality_data.csv` with paired original and corrected text (not part of this release) |
| Figure S8 / choice-statement masking | `analyze_control_experiments.py` | Original and masked predictions, including the extraction-model-specific files below |
| Choice-statement prevalence | `analyze_superficial_claims.py` | Extraction CSVs generated by `exp_superficial_claims.py` |

After generating or obtaining those artifacts, analysis interfaces include:

```sh
python analyze_model_comparison.py --data_sizes small large
python analyze_in_context.py --data_size small
python analyze_in_context.py --data_size large
python analyze_cot_embeddings_similarity.py --embedding_dir results/embeddings --output_dir figures/embeddings_similarity
python analyze_superficial_claims.py
```

For the manuscript's GPT-5.4-nano extraction-based masking analysis, explicitly select:

```sh
python analyze_control_experiments.py --action_removal_results_filename_small meta-llama_Meta-Llama-3.1-70B-Instruct_small_action_removal_results-GPT-5.4-nano.json --action_removal_results_filename_large meta-llama_Meta-Llama-3.1-70B-Instruct_large_action_removal_results-GPT-5.4-nano.json --output_suffix _GPT-5.4-nano
```

LLaMA-extracted masks and GPT-extracted masks are different analysis inputs; do not silently substitute one for the other. Model-response regeneration is not guaranteed to recover identical outputs from changed remote services or different hardware/software.

## 5. Known source limitations

- `exp1_cognitive_modeling.py` is retained as a legacy source artifact, **not a working CLI**: it imports the absent `DATA_PATHS` config and uses model interfaces that differ from `models/cognitive_models.py`. Its repair and numerical validation are outside this data-release pass. Use the model definitions for inspection; do not treat this wrapper as a verified reproduction of the baselines.
- The historical `utils/data_processing.py` evaluates list strings with `eval`. Use it only with trusted original inputs. The public reading example uses `ast.literal_eval`.
- Auxiliary inputs and historical predictions/embeddings are not included. Scripts requiring them will not complete from a fresh clone. This release provides the core trial data and relevant source, not a complete archived analysis runtime. Recovered collection materials and the Experiment 1 reconstruction are documented in [study materials](../materials/README.md).
- The CSV nonblank-text count discrepancy is documented in the [data dictionary](../data/README.md). No numerical result was changed in packaging.
